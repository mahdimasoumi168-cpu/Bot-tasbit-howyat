## پیش‌نمایش
نشانی آزمایشی: https://bot-tasbit-howyat-miniapp-preview.mahdi-masoumi168.workers.dev/app

این Worker جداگانه است و به webhook ربات اصلی متصل نشده است. در پیش‌نمایش، رابط بصری و فهرست خدمات قابل مشاهده است؛ APIهای وابسته به نشست تلگرام و پایگاه داده تا تنظیم Secret و D1 کامل فعال نیستند.

## معماری هدف
- Cloudflare Worker: رابط مینی‌اپ، API و webhook پس از آزمون.
- D1: کاربران، وضعیت فرم، خدمات، پرونده‌ها، اعتبار، رسیدها، تیکت‌ها و جلوگیری از پردازش تکراری.
- R2: نگهداری امن فایل‌های پیوست در مرحله‌ی بعد؛ در D1 فقط شناسه/فراداده نگهداری شود.
- Secrets: `BOT_TOKEN`، `WEBHOOK_SECRET` و کلیدهای درگاه؛ هیچ‌کدام داخل Git ثبت نشوند.
- پنل مدیریت/اپراتور: مسیر جدا با مجوز سروری؛ نمایش/مخفی‌کردن رابط به‌تنهایی کنترل امنیتی نیست.

## اصول ایمنی
1. هیچ توکن یا کلید پرداختی در این پوشه یا GitHub قرار نگیرد.
2. هر webhook با `update_id` یکتا پردازش شود؛ اگر پردازش خطا خورد، علامت تکراری پاک شود تا تلگرام بتواند تلاش مجدد کند. قبل از استفاده‌ی عملیاتی، کنترل هم‌زمانی نیز باید آزمون شود.
3. پرداخت فقط پس از تأیید مستقیم از API درگاه معتبر شود؛ callback به‌تنهایی سند پرداخت نیست.
4. تغییر وضعیت پرونده و اعتبار باید در تراکنش پایگاه داده انجام شود.
5. مهاجرت ابتدا در شاخه‌ی جداگانه و با نسخه‌ی آزمایشی انجام می‌شود؛ Worker فعال فقط پس از آزمون جایگزین خواهد شد.
6. پروژه‌ی Railway و شاخه‌ی `main` تا تأیید نهایی حفظ می‌شوند.
7. قیمت‌ها در داده‌ی فعلی تاریخی و متناقض‌اند؛ هیچ مبلغی برای پرداخت یا عرضه‌ی عمومی نهایی تلقی نشود تا از تنظیمات جاری پروژه تأیید شود.

## راه‌اندازی محلی
1. فایل `cloudflare/wrangler.toml.example` را به فایل تنظیمات محلی تبدیل و شناسه‌ی واقعی D1 را فقط پس از ایجاد پایگاه داده وارد کنید.
2. Secretها را از داشبورد Cloudflare یا Wrangler تنظیم کنید؛ هرگز مقدار Secret را در Git قرار ندهید.
3. پس از بازبینی schema، پایگاه داده را با دستور زیر مقداردهی کنید:

```sh
npx wrangler d1 execute bot-tasbit-howyat-db --remote --file=cloudflare/schema.sql
```

4. پیش از انتشار نسخه‌ی یکپارچه، آزمون‌های API، مجوزهای مدیر، مسیر فرم‌ها، پرداخت‌ها، تکرار webhook و بازیابی خطا را انجام دهید.
