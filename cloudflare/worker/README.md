# انتقال کمک‌یار مهاجر به Cloudflare

این پوشه، نسخه جدید Cloudflare Worker و Telegram Mini App است. نسخه Python/aiogram فعلی در ریشه مخزن حفظ می‌شود تا تا پایان مهاجرت و تطبیق داده‌ها قابل بازگشت باشد.

## زیرساخت موجود که بررسی شد
- Worker موجود: `bot-tasbit-howyat`
- زیردامنه workers.dev حساب فعال است.
- Secret bindingهای موجود روی Worker: `BOT_TOKEN`, `RIALIT_API_KEY`, `API_VPN` (مقدارها عمداً خوانده یا در مخزن ثبت نشده‌اند).
- D1 موجود: `bot-tasbit-howyat-migration` با شناسه `f7a2d3ed-81f6-4e06-9e12-54507efd367b`؛ در بررسی 2026-11-02 تعداد جدول‌ها صفر بود.
- R2 در حساب هنوز فعال نشده است؛ فعال‌سازی آن باید از داشبورد Cloudflare انجام شود.

## راه‌اندازی محلی
```bash
cd cloudflare/worker
npm install
npm run typecheck
npm run dev
```

## مهاجرت D1
قبل از اجرای migration روی دیتابیس واقعی، از SQLite موجود در Railway در مسیر volume `/data` نسخه پشتیبان مستقل تهیه کنید. سپس جدول‌ها و رکوردها با حفظ شناسه‌ها و timestampها وارد D1 شوند. فایل `migrations/0001_initial.sql` ساختار مقصد را می‌سازد؛ این فایل به‌تنهایی داده‌های قدیمی را منتقل نمی‌کند.

```bash
npm run d1:migrate:remote
```

این فرمان را تا زمان گرفتن و تأیید پشتیبان Railway اجرا نکنید.

## Secrets
Worker فعلی در Cloudflare از قبل secretهای `BOT_TOKEN`, `RIALIT_API_KEY`, `API_VPN` دارد. در زمان انتشار باید این secretها روی همان Worker حفظ شوند. مقدار هیچ secret نباید وارد GitHub، Mini App یا log شود. `TELEGRAM_WEBHOOK_SECRET` نیز باید به‌صورت secret جدید تنظیم شود.

## ریالت‌پی و کارمزد ۱۲٪
- طبق OpenAPI فایل `rialit-api.yaml`، درخواست `POST /send` فقط `amount`, `order_id`, `payer_id` را می‌پذیرد. فیلدهایی مثل `payer_fee_bps` مجاز نیستند.
- کارمزد پرداخت‌کننده از بخش تنظیمات پذیرنده در داشبورد ریالت تنظیم می‌شود؛ API مبلغ پایه را می‌گیرد و `payer_amount` و `payer_fee` واقعی را برمی‌گرداند.
- برای کارمزد ۱۲٪، تنظیم Merchant باید در داشبورد روی ۱۲٪ قرار بگیرد. کد مبلغ پایه را ارسال می‌کند و مبلغ نهایی واقعی را از پاسخ ریالت ذخیره و نمایش می‌دهد.
- طبق فرمول مستندات ریالت، برای مبلغ پایه ۱۰۰٬۰۰۰ تومان، مبلغ پرداخت‌کننده با کارمزد ۱۲٪ برابر ۱۱۳٬۶۵۰ تومان (گرد شده به مضرب ۵۰) است.
- حد پرداخت آنلاین ریالت ۵۰٬۰۰۰ تا ۱۰٬۰۰۰٬۰۰۰ تومان است. برای مبلغ خارج از بازه، کارت‌به‌کارت باید در دسترس بماند.
- وب‌هوک باید IPهای دقیق تب Webhook ریالت، هدرهای `X-Rialit-Event` و `X-Rialit-Delivery`، `event_id` یکتا و استعلام `GET /status/{token}` را بررسی کند.

## گذربان
فایل WebArchive گذربان در کتابخانه بررسی شد. رابط پنل مسیرهایی مانند `/api/user/subscriptions` و `/api/user/subscription/create` را نشان می‌دهد و صفحه مستندات از `/api/developer/openapi.json` بارگذاری می‌شود. خود OpenAPI JSON در WebArchive ذخیره نشده است؛ بنابراین شکل دقیق بدنه ساخت اشتراک و پاسخ‌ها هنوز از سند رسمی قابل تأیید نیست. ساخت اشتراک خودکار تا دریافت/استخراج همان OpenAPI و آزمون sandbox عمداً مسدود است.

## Cutover
1. پشتیبان SQLite و فایل‌های رسید/شناسه‌های تلگرام تهیه شود.
2. تعداد و checksum جدول‌های مبدأ ثبت و داده‌ها به D1 وارد شوند.
3. تست تطبیق تعداد کاربران، پرونده‌ها، موجودی‌ها، تراکنش‌ها و پرداخت‌های قدیمی اجرا شود.
4. تست ریالت با Merchant fee=12% و webhook test انجام شود.
5. Mini App و bot webhook آزمایش شوند.
6. تنها پس از قبولی تست‌ها، webhook تلگرام به Worker منتقل و polling قدیمی متوقف شود.
7. Railway و volume تا پایان دوره اطمینان‌سنجی خاموش/حذف نشوند.
