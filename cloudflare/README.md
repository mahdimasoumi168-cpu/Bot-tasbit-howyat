# مهاجرت Cloudflare برای کمک‌یار مهاجر

این پوشه نسخه‌ی مستقل مهاجرت است. نسخه‌ی Python روی شاخه‌ی `main` دست‌نخورده می‌ماند و تا پایان آزمون‌ها حذف یا جایگزین نمی‌شود.

## وضعیت
- [x] شاخه‌ی جداگانه‌ی `cloudflare-migration` ساخته شد.
- [ ] طرح داده‌ی D1 بازبینی و ایجاد شود.
- [ ] توکن ربات فقط به‌صورت Secret تنظیم شود.
- [ ] منطق فرم‌ها و پنل‌های مشترک، اپراتور و مدیریت منتقل شود.
- [ ] درگاه‌ها با تأیید سمت سرور و جلوگیری از پرداخت تکراری منتقل شوند.
- [ ] آزمون‌های مسیرهای اصلی و webhook انجام شود.
- [ ] فقط پس از تأیید، webhook نهایی به Worker منتقل شود.

## معماری هدف
- Cloudflare Worker: دریافت Telegram webhook و پردازش رویدادها.
- D1: کاربران، وضعیت فرم، خدمات، پرونده‌ها، اعتبار، رسیدها، تیکت‌ها و جلوگیری از پردازش تکراری.
- R2 (مرحله‌ی بعد): نگهداری فایل‌های پیوست در صورت نیاز؛ در D1 فقط شناسه/فراداده نگهداری شود.
- Secrets: `BOT_TOKEN`، `WEBHOOK_SECRET` و کلیدهای درگاه؛ هیچ‌کدام داخل Git ثبت نشوند.

## اصول ایمنی
1. هیچ توکن یا کلید پرداختی در این پوشه یا GitHub قرار نگیرد.
2. هر webhook با `update_id` یکتا پردازش شود تا تکرار درخواست، پرونده یا شارژ تکراری نسازد.
3. پرداخت فقط پس از تأیید مستقیم از API درگاه معتبر شود؛ callback به‌تنهایی سند پرداخت نیست.
4. تغییر وضعیت پرونده و اعتبار باید در تراکنش پایگاه داده انجام شود.
5. مهاجرت ابتدا در شاخه‌ی جداگانه و با نسخه‌ی آزمایشی انجام می‌شود؛ Worker فعال فقط پس از آزمون جایگزین خواهد شد.
6. پروژه‌ی Railway و شاخه‌ی `main` تا تأیید نهایی حفظ می‌شوند.

## اجرای طرح داده
پس از ساخت D1:
```sh
npx wrangler d1 execute bot-tasbit-howyat-db --remote --file=cloudflare/schema.sql
```

شناسه‌ی واقعی D1 باید در فایل تنظیمات محلی Wrangler وارد شود؛ فایل حاوی شناسه یا اسرار محیطی نباید حاوی توکن باشد.
